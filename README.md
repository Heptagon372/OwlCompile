# OWL COMPILE 실행 안내

S.OWL 오리엔테이션용 팀 코딩 게임입니다. 4명이 한 팀이 되어 블록 명령어 카드를 연결하고, 부엉이를 둥지까지 보냅니다.
진행자가 실행을 누르면 팀 코드가 프로젝터에서 한 칸씩 재생됩니다. 게임은 5라운드입니다.

이 문서는 행사를 운영하는 동아리원을 위한 안내입니다. Next.js를 몰라도 순서대로 따라 하면 됩니다.

## 1. 준비물

- **Node.js 20 이상** (22 권장). [nodejs.org](https://nodejs.org)에서 LTS 버전을 설치합니다.
- **행사 PC 1대.** 서버, 진행자 화면, 프로젝터 화면을 한 PC에서 모두 돌릴 수 있습니다. 프로젝터는 두 번째 모니터로 연결합니다.
- **참가자 폰.** 브라우저만 있으면 됩니다. 앱 설치는 필요 없습니다.
- **모두 같은 와이파이.** 행사 PC와 참가자 폰이 같은 와이파이에 연결되어 있어야 합니다.

Node.js 버전은 명령 프롬프트나 PowerShell에서 확인합니다.

```bash
node -v
```

## 2. 설치와 실행

아래 명령은 모두 프로젝트 폴더(`package.json`이 있는 폴더)에서 실행합니다.
폴더 경로에 공백이나 한글이 있으면 `cd "C:\...\OwlCompile"`처럼 따옴표로 감쌉니다.

1. 필요한 패키지를 설치합니다. 처음 한 번만 하면 됩니다.

   ```bash
   npm install
   ```

2. 사이트를 빌드합니다. 코드를 받거나 고친 뒤에는 다시 빌드합니다.

   ```bash
   npm run build
   ```

3. 서버를 켭니다. 기본 주소는 `http://localhost:3000`입니다.

   ```bash
   npm start
   ```

4. 행사가 끝날 때까지 이 창을 닫지 않습니다. 서버를 끄려면 그 창에서 `Ctrl + C`를 누릅니다.

다른 포트로 열려면 `--` 뒤에 `-p 포트번호`를 붙입니다. 아래는 4000번 포트로 여는 예입니다.

```bash
npm start -- -p 4000
```

개발할 때는 빌드 없이 코드 변경이 바로 반영되는 개발 서버를 씁니다. 개발 서버는 3000번 포트로 열립니다. 행사 당일에는 `npm run build` → `npm start`를 씁니다.

```bash
npm run dev
```

> **한 대의 PC에서 계속 켜 두는 Node 서버로만 돌아갑니다.** 실시간 화면 갱신(SSE)과 타이머가 서버 프로세스의 메모리에서 돌기 때문에, Vercel 같은 서버리스 배포에서는 동작하지 않습니다. 행사 PC, VPS, Render·Railway 같은 상주 서버에서 실행합니다.

## 3. 처음 한 번: 관리자 계정 만들기

1. 서버를 켠 뒤 브라우저로 `http://localhost:3000/setup`을 엽니다. 계정이 하나도 없으면 사이트 첫 화면도 이곳으로 보냅니다.
2. 아이디(영문·숫자·밑줄 3~20자), 표시 이름, 비밀번호(8자 이상)를 넣고 **관리자 계정 만들기**를 누릅니다.
3. 바로 로그인되고 관리 화면(`/admin`)으로 이동합니다.

`/setup`은 계정이 하나도 없을 때만 열립니다. 계정이 생긴 뒤에는 "페이지 없음"이 뜹니다.

관리자 비밀번호를 잊었거나 관리자 계정이 잠겼다면, 서버 PC에서 아래 명령으로 복구합니다.
같은 아이디가 이미 있으면 그 계정을 관리자·사용 중으로 되돌리고 비밀번호를 바꿉니다. 그 계정의 기존 로그인은 모두 끊깁니다.
아이디가 없으면 새 관리자 계정을 만듭니다.

```bash
npm run admin:create -- --username 아이디 --password 새비밀번호
```

표시 이름도 정하려면 `--name 이름`을 덧붙입니다.

## 4. 초대와 가입

이 사이트는 초대받은 사람만 가입할 수 있습니다. 이메일은 보내지 않습니다. 초대 링크를 복사해서 메신저로 보냅니다.

> **초대 링크는 폰에서 열리는 주소로 자동으로 만들어집니다.** 관리 화면을 `localhost`로 열어도 링크는 진행자 참가 안내와 같은 와이파이 주소가 됩니다. 초대 탭 위에 링크 주소와 그 링크가 어디서 열리는지가 표시됩니다. 와이파이 주소 링크는 이 PC와 같은 와이파이에서만 열립니다. 행사 전에 집에서 미리 가입하게 하려면 사이트를 인터넷에 공개된 서버에 올리고 `OWL_PUBLIC_URL`을 설정해야 합니다([환경 변수](#환경-변수)).

### 계정 역할

| 역할 | 할 수 있는 일 |
|---|---|
| 관리자 | 전부. 초대 만들기, 회원 관리, 모든 게임 관리, 게임 진행 |
| 진행자 | 게임 만들기, 진행자 콘솔, 프로젝터 보드 |
| 참가자 | 게임 참가, 팀 편집기 |

### 초대 탭 (`/admin` → 초대)

1. **메모 (한 줄에 한 명)** 칸에 이름을 한 줄에 하나씩 적습니다. 이름 목록을 그대로 붙여 넣어도 됩니다. 한 줄마다 초대 링크가 한 장씩 만들어집니다. 비워 두면 메모 없는 초대 한 장이 만들어집니다.
2. **역할**(참가자 또는 진행자)과 **만료 (일)**를 고릅니다. 만료는 기본 14일이고, 0이면 만료되지 않습니다. 한 번에 60장까지 만들 수 있습니다.
3. **초대 N장 만들기**를 누릅니다.
4. **방금 만든 것 복사**를 누르면 "메모 ⇥ 링크" 줄들이 복사됩니다. 단톡방에 붙여 넣고 각자 자기 이름 옆 링크를 열게 합니다.
5. 초대 목록에서는 한 장씩 **링크 복사**를 할 수 있고, **전체 복사**로 대기 중인 초대를 한 번에 복사할 수 있습니다.
6. 잘못 보낸 초대는 **취소**를 누릅니다. 그 링크로는 더 이상 가입할 수 없습니다.

초대 링크는 한 번만 쓸 수 있습니다. 링크를 연 사람은 아이디, 표시 이름, 비밀번호를 정하고 가입하며, 가입과 동시에 로그인됩니다.

### 회원 탭 (`/admin` → 회원)

- **역할 바꾸기:** 역할 칸에서 관리자·진행자·참가자 중 하나를 고릅니다. 자기 역할은 바꿀 수 없습니다.
- **사용 중지 / 재개:** 중지하면 그 사람은 바로 로그아웃되고 다시 로그인할 수 없습니다. 언제든 재개할 수 있습니다.
- **비밀번호 초기화:** 임시 비밀번호가 한 번만 표시됩니다. 창을 닫기 전에 복사해서 전달합니다. 그 사람은 다음 로그인 때 새 비밀번호를 정합니다.
- **삭제:** 계정과 게임 참가 기록이 지워집니다. 되돌릴 수 없습니다. 자기 자신과 마지막 관리자는 삭제할 수 없습니다.

### 게임 탭 (`/admin` → 게임)

모든 게임 목록을 보고, 게임 콘솔을 열거나 게임을 삭제합니다.

## 5. 게임 진행 순서

### 준비

1. 진행자(또는 관리자) 계정으로 로그인하고 `/host`를 엽니다. 홈 화면의 **진행자 화면**을 눌러도 됩니다.
2. **새 게임**에서 팀 수(4~6팀)를 고르고 **N팀으로 게임 만들기**를 누릅니다. 팀 이름과 색은 수리부엉이, 올빼미, 소쩍새, 흰올빼미, 금눈쇠올빼미, 칡부엉이 순서로 정해집니다.
3. 진행자 콘솔(`/host/게임코드`)이 열립니다. 왼쪽 아래 **참가 안내**에 접속 주소와 4자리 게임 코드가 크게 보입니다.
4. **보드 열기**를 눌러 프로젝터 화면을 띄웁니다([6. 프로젝터](#6-프로젝터)). 대기실 보드에도 접속 주소와 게임 코드가 크게 나옵니다.

### 참가자 입장

1. 참가자는 폰으로 사이트에 로그인합니다.
2. 홈의 **게임 참가**에 게임 코드 4자리를 넣거나, `/join`을 엽니다.
3. 팀을 고르고 빈 역할(러너, 터너, 컨트롤러, 아키텍트)을 누른 뒤 **참가하기**를 누릅니다. 팀이 4명보다 적으면 한 사람이 역할을 여러 개 맡아도 됩니다.
4. 참가는 대기실이나 코딩 중일 때만 됩니다.

### 라운드 진행

진행자 콘솔 왼쪽의 큰 버튼 하나가 다음 단계로 넘깁니다. 버튼 이름은 단계마다 바뀝니다.

| 지금 단계 | 누를 버튼 | 일어나는 일 |
|---|---|---|
| 대기실 | **코딩 시작** | 라운드가 시작되고 타이머가 자동으로 돕니다. 팀들이 폰에서 카드를 연결합니다 |
| 코딩 중 | **봉인** | 코딩을 끝냅니다. 아직 제출하지 않은 팀은 지금 코드 그대로 자동 봉인되고 제출 순서는 맨 뒤로 갑니다. 타이머가 0이 되어도 자동으로 봉인됩니다 |
| 봉인 | **실행** | 서버가 제출 순서대로 모든 팀 코드를 실행합니다 |
| 실행 | **점수 확정** | 모든 팀 재생을 다 본 뒤 누릅니다. 보드에 라운드 점수와 누적 순위가 나옵니다 |
| 점수 발표 | **다음 라운드** | 다음 라운드의 코딩이 시작됩니다 (R1~R4) |
| 점수 발표 (R5) | **최종 순위** | 보드에 최종 순위가 나옵니다 |

- **실행 단계:** **실행**을 누르면 제출 순서 첫 팀이 보드에서 바로 재생됩니다. 가운데 **실행 순서** 영역의 **다음 팀**으로 한 팀씩 넘기거나 **자동 진행**에 맡깁니다. **자동 진행**이 켜져 있으면 한 팀 재생이 끝나고 몇 초 뒤 다음 팀으로 자동으로 넘어갑니다. 팀 이름을 누르면 그 팀을 다시 보여 줍니다.
- **타이머:** 코딩 중에 **일시정지**, **타이머 시작**(다시 돌리기), **+30초**를 쓸 수 있습니다.
- **팀 코드와 정답:** 팀 표에서 팀을 누르면 오른쪽에 그 팀 코드와 검사 결과가 보입니다. **정답 보기**는 진행자 화면에만 보입니다. 프로젝터에는 나오지 않습니다.
- **패치권:** 실행 결과가 에러·사망·미도착인 팀은 팀마다 한 번 **패치 허용**을 받을 수 있습니다. 그 팀 편집기만 다시 열립니다. 팀이 고쳐서 다시 제출하면 **재실행**을 누릅니다. 재실행 점수에서 10점이 빠집니다. 패치를 허용하고 재실행하지 않은 팀이 있으면 점수 확정 버튼이 막힙니다.
- **보너스:** 이벤트 카드처럼 규칙 밖 점수는 오른쪽 **보너스 점수 더하기**에 점수(−100~100, 0 제외)와 메모를 넣고 **보너스 더하기**를 누릅니다.
- **팀원 내보내기:** 잘못 들어온 사람은 오른쪽 팀원 목록에서 **내보내기**를 누릅니다. 그 역할이 비워집니다.
- **이전 페이즈로:** 버튼을 잘못 눌렀으면 **이전 페이즈로**를 누릅니다. 실행에서 봉인으로 돌아가면 그 라운드의 실행 결과와 보너스 점수가 지워집니다. 확인 창에 무엇이 지워지는지 나오므로 읽고 누릅니다.

## 6. 프로젝터

1. 프로젝터를 행사 PC의 두 번째 화면으로 연결합니다. Windows 설정에서 디스플레이를 **확장**으로 둡니다.
2. 진행자 콘솔의 **보드 열기**를 누르면 새 탭에 `/board/게임코드`가 열립니다.
3. 그 탭을 새 창으로 떼어 프로젝터 화면으로 옮깁니다.
4. 프로젝터 화면에서 **F11**을 눌러 전체 화면으로 만듭니다. 다시 누르면 돌아옵니다.

보드는 1920×1080 화면에 맞춰 만들어졌고, 창 크기에 따라 자동으로 확대·축소됩니다.
보드는 진행자 콘솔과 같은 브라우저(같은 로그인)로 엽니다. 이 게임의 진행자나 관리자만 볼 수 있습니다.
보드를 새로고침하면 재생 중이던 팀은 마지막 장면으로 바로 보입니다.

## 7. 폰 접속

폰에서 `localhost`는 폰 자신을 뜻하므로 열리지 않습니다. 폰은 행사 PC의 **와이파이 IP 주소**로 접속합니다.

1. **폰 주소는 참가 안내에서 읽습니다.** 진행자 콘솔 왼쪽 아래 **참가 안내**와 보드 대기실 화면은 이 PC의 와이파이(LAN) 주소를 스스로 찾아 크게 보여 줍니다(예: `192.168.0.23:3000/join`). 콘솔을 `localhost`로 열었어도 와이파이 주소가 나옵니다.
2. 와이파이 주소(`192.168.x.x` 등)가 맨 앞에 크게 나옵니다. Tailscale 같은 VPN 주소(`100.64.0.0/10`, 예: `100.87.x.x`)는 **VPN** 표시와 함께 맨 뒤에 나옵니다. 와이파이만 쓰는 폰은 VPN 주소로 들어올 수 없습니다.
3. `npm start`가 서버 창에 찍는 `Network: http://…` 줄로 주소를 알리지 않습니다. VPN(Tailscale 등)이 켜진 PC에서는 그 줄에 VPN 주소가 나올 수 있습니다. 한 번 더 확인하려면 PowerShell에서 `ipconfig`를 실행해 **무선 LAN 어댑터 Wi-Fi** 항목의 **IPv4 주소**가 참가 안내의 주소와 같은지 봅니다.

   ```bash
   ipconfig
   ```

4. 참가 안내에 **"이 주소는 이 PC에서만 열립니다. 와이파이 주소를 찾지 못했어요."**가 뜨면 서버가 이 PC의 와이파이(LAN) 주소를 찾지 못한 것입니다. PC가 와이파이에 연결되어 있는지 확인하고 콘솔을 새로고침합니다. 그래도 안 되면 환경 변수 `OWL_PUBLIC_URL`로 주소를 직접 정합니다([환경 변수](#환경-변수)).
5. **로그인은 주소별로 따로 기억됩니다.** `localhost`로 로그인했다면 콘솔도 계속 `localhost`로, 와이파이 주소로 로그인했다면 그 주소로 엽니다. 초대 링크는 어느 주소로 열든 참가 안내와 같은 주소로 만들어집니다([4. 초대와 가입](#4-초대와-가입), [8. 계정 전환](#8-계정-전환)). 포트를 바꿨다면 그 번호를 씁니다.

### 폰이 접속하지 못할 때

- **같은 와이파이인지** 확인합니다. 폰이 모바일 데이터나 다른 와이파이에 붙어 있으면 열리지 않습니다.
- **Windows 방화벽.** 서버를 처음 켤 때 **Windows 보안 경고** 창이 뜨고 "Node.js JavaScript Runtime"의 네트워크 접근을 묻습니다. **개인 네트워크**에 체크하고 **액세스 허용**을 누릅니다. 창이 서버 창 뒤에 숨어 있을 수 있으니 작업 표시줄도 확인합니다.
- 그 창에서 취소를 눌렀다면: **Windows 보안 → 방화벽 및 네트워크 보호 → 방화벽에서 앱 허용**에서 **설정 변경**을 누르고, Node.js 항목의 **개인** 칸에 체크합니다.
- 와이파이가 **공용 네트워크**로 잡혀 있으면 개인 네트워크 허용이 적용되지 않습니다. **설정 → 네트워크 및 인터넷 → Wi-Fi → 연결된 와이파이 → 네트워크 프로필 유형**을 **개인 네트워크**로 바꿉니다. 행사장처럼 믿을 수 있는 와이파이에서만 바꿉니다.
- 방화벽을 통째로 끄지 않습니다. Node.js만 개인 네트워크에서 허용하면 충분합니다.
- 학교·카페 와이파이는 기기끼리 통신을 막아 두기도 합니다. 위를 모두 확인해도 안 되면 동아리 공유기나 휴대폰 핫스팟에 행사 PC와 폰을 함께 연결합니다.

## 8. 계정 전환

한 브라우저는 한 번에 한 계정만 로그인해 둘 수 있습니다.

- 다른 계정으로 바꾸려면 상단 바의 **로그아웃**을 누른 뒤 다시 로그인합니다.
- 이미 로그인된 브라우저에서 `/login`이나 초대 링크를 열면 지금 로그인된 계정이 표시됩니다. **이 계정으로 계속**을 누르거나, **로그아웃하고 다른 계정으로 로그인**(초대 링크에서는 **로그아웃하고 새 계정으로 가입**)을 눌러 그 자리에서 바꿉니다.
- 두 계정을 동시에 써야 하면(예: 진행자 콘솔과 참가자 화면을 한 PC에서 시험) 한쪽을 **시크릿 창**(Chrome `Ctrl + Shift + N`, Edge `Ctrl + Shift + N`)으로 엽니다.
- 로그인은 주소별로 따로 기억됩니다. `localhost`로 로그인했어도 IP 주소로 열면 다시 로그인해야 합니다.

## 9. 데이터

모든 계정, 초대, 게임, 점수는 파일 하나에 저장됩니다.

- 위치: 프로젝트 폴더의 `data/owl.db` (다른 위치를 쓰려면 환경 변수 `OWL_DB_PATH`)
- 옆에 `owl.db-wal`, `owl.db-shm` 파일이 함께 생길 수 있습니다. 같은 데이터의 일부입니다.

**백업:** 서버를 끈 뒤(`Ctrl + C`) `data` 폴더의 `owl.db`(과 `owl.db-wal`, `owl.db-shm`이 있으면 함께)를 다른 곳에 복사합니다. 서버가 켜진 채로 복사하면 파일이 깨질 수 있습니다.

**초기화:** 서버를 끈 뒤 `data/owl.db`(과 `owl.db-wal`, `owl.db-shm`)를 지웁니다. **모든 계정과 게임이 지워집니다.** 서버를 다시 켜면 빈 DB가 만들어지고, `/setup`에서 관리자부터 다시 만듭니다.

## 10. 명령어

| 명령 | 하는 일 |
|---|---|
| `npm install` | 패키지 설치 (처음 한 번) |
| `npm run build` | 행사용 빌드 |
| `npm start` | 빌드한 사이트 실행 (기본 3000번 포트, `npm start -- -p 4000`으로 변경) |
| `npm run dev` | 개발 서버 (3000번 포트, 코드 변경 즉시 반영) |
| `npm run verify` | 게임 엔진 규칙과 5개 맵의 기대값을 검사 |
| `npm run test` | 단위 테스트 (vitest) |
| `npm run e2e:api` | 켜져 있는 서버에 붙어 관리자 → 초대 → 가입 → 게임 → R1~R5를 끝까지 도는 API 시험. **빈 DB로 켠 서버**에서 돌립니다 (아래 참고) |
| `npm run admin:create -- --username 아이디 --password 비밀번호` | 관리자 계정 만들기·복구 |
| `npm run sync:engine` | `engine/`을 `lib/engine/`으로 복사. `dev`, `build`, `test` 전에 자동 실행되므로 보통 직접 칠 일은 없습니다 |
| `npm run build:doc` | 설계서 `docs/DESIGN.md`, `docs/design.html`을 다시 만듭니다 |

`e2e:api`는 계정이 하나도 없는 서버가 필요합니다. 행사용 DB를 건드리지 않도록 별도 DB 파일과 별도 포트로 서버를 켜고 돌립니다. Git Bash 기준 예시입니다.

```bash
OWL_DB_PATH=data/e2e.db npx next start -p 3100
```

다른 창에서 실행합니다.

```bash
BASE_URL=http://localhost:3100 npm run e2e:api
```

다시 돌릴 때는 서버를 끄고 `data/e2e.db*` 파일을 지운 뒤 켭니다.

## 11. 문제 해결

| 증상 | 해결 |
|---|---|
| 서버를 켤 때 `EADDRINUSE` (포트가 이미 사용 중) | 이미 켜 둔 서버 창이 있는지 확인하고 그 창에서 `Ctrl + C`로 끕니다. 아니면 `npm start -- -p 4000`처럼 다른 포트로 켜고, 폰에도 그 포트로 알려 줍니다 |
| 폰에서 사이트가 안 열림 | 폰 주소가 `localhost`가 아니라 PC의 IP인지, 같은 와이파이인지, Windows 방화벽에서 Node.js가 개인 네트워크에 허용됐는지, 와이파이가 개인 네트워크로 잡혔는지 확인합니다 ([7. 폰 접속](#7-폰-접속)) |
| 버튼을 누르면 "다른 사이트에서 온 요청은 받을 수 없습니다" | 사이트를 한 가지 주소로만 엽니다. `localhost`와 IP 주소를 섞어 쓰거나, 주소가 바뀐 뒤 예전 탭을 계속 쓰면 생깁니다. 행사 주소로 새로 열고 다시 로그인합니다 |
| 초대 링크에 `localhost`가 보이거나 초대 탭에 "이 PC에서만 열리는 주소" 안내가 뜸 | 서버가 이 PC의 와이파이 주소를 찾지 못했습니다. PC가 와이파이에 연결되어 있는지 확인하고 새로고침한 뒤 초대를 새로 만듭니다. 그래도 안 되면 `OWL_PUBLIC_URL`로 주소를 정합니다. 이미 보낸 `localhost` 링크는 주소 부분만 와이파이 주소로 바꿔 열어도 됩니다 |
| 참가 안내에 `localhost`가 보이거나 "이 주소는 이 PC에서만 열립니다"가 뜸 | 서버가 이 PC의 와이파이(LAN) 주소를 찾지 못했습니다. PC가 와이파이에 연결되어 있는지 확인하고 새로고침합니다. 그래도 안 되면 `OWL_PUBLIC_URL`로 주소를 직접 정합니다 ([7. 폰 접속](#7-폰-접속)) |
| 참가 안내의 큰 주소가 `100.`으로 시작하거나 **VPN** 표시가 붙음 | Tailscale 같은 VPN 주소입니다. 와이파이만 쓰는 폰은 들어올 수 없습니다. PC가 행사 와이파이에 연결되어 있는지 확인하거나, `OWL_PUBLIC_URL`로 와이파이 주소를 정합니다 |
| 로그인 화면이나 초대 링크에 "지금 ○○ 계정으로 로그인되어 있습니다"가 뜸 | 그 브라우저가 이미 다른 계정으로 로그인되어 있습니다. 그 계정이 맞으면 **이 계정으로 계속**, 아니면 **로그아웃하고 다른 계정으로 로그인**(초대 링크에서는 **로그아웃하고 새 계정으로 가입**)을 누릅니다 ([8. 계정 전환](#8-계정-전환)) |
| 관리자 비밀번호를 잊음 | 서버 PC에서 `npm run admin:create -- --username 아이디 --password 새비밀번호` ([3. 처음 한 번](#3-처음-한-번-관리자-계정-만들기)). 다른 회원은 관리자가 회원 탭의 **비밀번호 초기화**로 풀어 줍니다 |
| 화면에 "다시 연결하는 중…"이 뜸 | 서버가 꺼졌거나 와이파이가 끊겼습니다. 서버 창이 켜져 있는지 확인합니다. 다시 연결되면 자동으로 최신 상태로 돌아옵니다 |

### 환경 변수

| 이름 | 뜻 |
|---|---|
| `OWL_DB_PATH` | SQLite 파일 경로. 기본 `data/owl.db` |
| `OWL_PUBLIC_URL` | 폰 참가 주소를 직접 정합니다. `http://192.168.0.23:3000`이나 `https://owl.example.com`처럼 `http://`·`https://`로 시작하는 주소 하나를 넣으면, 진행자 콘솔의 참가 안내와 보드 대기실이 자동 감지 대신 이 주소만 보여 줍니다. 경로는 떼고 `스킴://호스트:포트`만 씁니다. 잘못된 값(스킴 없음 등)이나 `localhost`·`127.0.0.1` 같은 이 PC 전용 주소는 무시하고 자동 감지를 쓰며, 서버 창에 경고가 한 번 찍힙니다. 초대 링크도 이 주소로 만들어집니다. PowerShell에서는 `$env:OWL_PUBLIC_URL = "http://192.168.0.23:3000"`을 실행한 뒤 같은 창에서 `npm start`를 실행합니다 |
| `OWL_TRUST_PROXY` | `1`이면 앞단 프록시(nginx 등)가 붙인 `X-Forwarded-For`(오른쪽 끝 값)·`X-Real-IP`·`X-Forwarded-Host`·`X-Forwarded-Proto`를 믿습니다. 행사 PC에서 `npm start`로 바로 열 때는 설정하지 않습니다. 클라이언트가 이 헤더를 마음대로 넣어 로그인 시도 제한을 피할 수 있기 때문입니다. 설정하지 않으면 클라이언트 IP를 알 수 없으므로 아이디+IP 제한(5분 10회)은 쓰지 않고, 아이디 단위의 넉넉한 제한(5분 100회)만 걸립니다. 여러 사람이 접속하는 인터넷 배포에서는 프록시 뒤에 두고 `OWL_TRUST_PROXY=1`로 켭니다. TLS를 프록시가 끝내는 경우 세션 쿠키에 Secure를 붙이려면 반드시 켭니다 |
