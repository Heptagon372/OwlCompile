# OWL COMPILE v5 — 나이트 모드 · 라이트 모드 (UI만)

사용자 요청(2026-09-14): "나이트 모드, 라이트 모드 만들어줘. 해하고 달인데 옆으로 넘어가는 모션으로."
기존 v4 디자인(`docs/DESIGN_V4.md`)이 **나이트 모드**다. 이 문서는 같은 구조와 부품 위에 **라이트 모드**를 더하고, 둘 사이를 오가는 **해·달 토글**을 정의한다. 기능·서버·엔진은 바꾸지 않는다. (브리프의 "다크/라이트 전환 안 만든다"는 폐기)

## 1. 동작

- 모드: `night`(기본), `light`. 첫 방문(저장값 없음)은 나이트.
- 저장: 쿠키 `owl_theme=night|light` (Path=/, 1년, SameSite=Lax, httpOnly 아님) + 같은 값을 localStorage에도. 서버 루트 레이아웃이 쿠키를 읽어 `<html data-theme="…">`로 렌더링한다 → 새로고침해도 깜빡임 없음.
- 토글 위치: 앱 셸 헤더 오른쪽(모든 셸 페이지), 로그인·가입·설정 화면 오른쪽 위, 대기실 헤더. 프로젝터(/board)는 토글을 두지 않고 그 브라우저의 저장값을 따른다(진행자가 콘솔에서 바꾸면 같은 브라우저의 보드도 바뀐다: storage 이벤트로 즉시 반영).
- 탭 여러 개: 한 탭에서 바꾸면 다른 탭도 `storage` 이벤트로 바로 따라간다.

## 2. 해·달 토글 (핵심 연출)

- 모양: 가로 알약 스위치 72×36px(폰에서도 44px 이상 터치 영역 확보: 바깥 여백 포함).
  - **트랙**: 나이트 = 짙은 남보라 밤하늘 그라데이션 + 작은 별 3~5개(반짝임). 라이트 = 연한 하늘색→라벤더 그라데이션 + 작은 구름 1~2개.
  - **손잡이(원형 28px)**: 라이트 = 왼쪽에 **해**(따뜻한 금색 원 + 짧은 햇살), 나이트 = 오른쪽에 **달**(은빛 초승달, 달 표면 점 2~3개).
- **옆으로 넘어가는 모션** (0.6초, ease 곡선 cubic-bezier(.65,0,.35,1)):
  - 라이트 → 나이트: 손잡이가 왼쪽에서 오른쪽으로 미끄러진다. 그동안 해는 오른쪽으로 굴러가며 트랙 아래로 지고(회전 + 아래로 사라짐), 달이 왼쪽 위에서 떠올라 손잡이 자리에 자리 잡는다. 트랙 배경은 하늘에서 밤하늘로 옆으로 흘러간다(배경 위치 이동). 구름이 오른쪽으로 빠지고 별이 하나씩 켜진다.
  - 나이트 → 라이트: 거울 방향으로 반대.
  - SVG 요소들의 transform/opacity만 움직인다(레이아웃 흔들림 없음).
- **화면 전환**: 모드가 바뀔 때 페이지 전체가 손잡이가 미끄러지는 방향으로 **옆으로 쓸려 넘어가며** 새 모드로 바뀐다. View Transitions API(`document.startViewTransition`)로 새 화면을 0.6초 드러낸다: 라이트→나이트는 왼쪽에서 오른쪽(`clip-path: inset(0 100% 0 0)` → `inset(0)`, 손잡이가 왼쪽→오른쪽), 나이트→라이트는 오른쪽에서 왼쪽 = 토글 쪽에서 반대쪽(`inset(0 0 0 100%)` → `inset(0)`). 지원하지 않는 브라우저는 0.3초 색 교차 전환. 보이지 않는 탭에서는 즉시 바뀐다.
- `prefers-reduced-motion`: 손잡이·아이콘만 즉시 바뀌고 화면 전환 없음.
- 접근성: `<button type="button" role="switch" aria-checked={night}>`, 라벨 "나이트 모드" (aria-label 동적: "라이트 모드로 바꾸기" / "나이트 모드로 바꾸기"), 키보드 Space·Enter, 포커스 링 보임, 툴팁 "라이트 모드" / "나이트 모드".

- 바탕 연출: 흰 라벤더 바탕 + 아주 옅은 보라·하늘색 라디얼 빛 2개 + 흐린 격자(투명도 낮게). 네온 글로우는 그림자 대신 **은은한 컬러 그림자**로 약하게(라이트에서 강한 발광은 촌스러움).
- 유리 패널: 흰 반투명 + blur + 윗변 흰 반사 + 아래 부드러운 보라 그림자(0 18px 50px rgba(60,40,140,.12)).
- 주 버튼: 같은 violet 그라데이션 알약(흰 글자), 빛 대신 그림자.
- 블록: 채움 블록(이동·회전·제어·특수)은 색 그대로(흰 바탕에서도 잘 보이도록 그림자 색만 옅게). 함수(유리형) 블록은 라이트에서 라벤더 채움 rgba(106,61,240,.10) + 1.5px #6A3DF0 테두리 + 글자 #3B1FA8.
- 코드 뷰(라이트): 바탕 glass-inset, keyword #6A3DF0, builtin #0E7490, call #1A1430, number #B45309, punct #6A6488, comment #6E6890 (#8A84A6 은 glass-inset 위 약 3.4:1 이라 4.5:1 을 맞추려 짙게). 새 줄 연출은 네온 대신 **보라 형광펜 하이라이트**가 훑고 지나가며 옅어진다. 현재 실행 줄: 보라 12% 배경 + 왼쪽 3px 보라 막대.
- 맵(라이트): 바닥 #ECE8F7 + 격자 rgba(40,24,110,.06), 벽 #8A82AE(바닥 대비 3:1 이상) + 윗변 흰 반사, 구덩이 #1A1430 원 + 흰 테두리, 둥지 #0891B2 링, 순찰로 #D63A5E 점선, 글리프 색은 라이트 토큰으로.
- 대기실 GlowCube: 라이트에서는 유리 큐브 안의 빛을 보라 대신 은은한 흰빛+보라 테두리로.
- 대비: 두 모드 모두 본문 4.5:1, 큰 글자·UI 경계 3:1 이상.

## 4. 구현 규칙

- 모든 색은 토큰으로. 컴포넌트·CSS에 박힌 rgba/hex(특히 글로우 그림자, 네온 text-shadow, 맵·보드 전용 값)는 토큰(`--glow-*`, `--neon-*`, `--map-*`, `--code-*` 등)으로 올려 두 모드 값을 준다.
- 루트 레이아웃: 쿠키 → `data-theme`, `color-scheme` 속성도 함께(light/dark) 설정해 폼 컨트롤·스크롤바가 맞게.
- `components/ui/ThemeToggle.tsx` (클라이언트), `lib/client/theme.ts` (읽기·쓰기·브로드캐스트·view transition). 서버 코드 변경은 레이아웃의 쿠키 읽기뿐.
- 테스트: 토글 로직 단위 테스트(쿠키·localStorage·data-theme 갱신), 두 모드 토큰 대비 계산 테스트.

## 5. 수용 기준

1. 셸 헤더·로그인 화면에 해·달 토글이 있고, 누르면 손잡이가 옆으로 미끄러지며 해가 지고 달이 뜬다(반대도 같다).
2. 화면 전체가 손잡이가 미끄러지는 방향으로 옆으로 쓸려 넘어가며 모드가 바뀐다(§2: 라이트→나이트 왼쪽→오른쪽, 나이트→라이트 토글 쪽→반대쪽; 지원 브라우저). 보이지 않는 탭·reduced-motion이면 즉시 바뀐다.
3. 새로고침·다른 페이지 이동·다른 탭에서도 선택한 모드가 유지되고, 깜빡임이 없다.
4. 라이트 모드에서 모든 화면(대기실, 홈, 관리, 진행자, 편집기, 프로젝터)의 글자·블록·맵·코드가 읽히고 대비 기준을 넘는다. 나이트 모드는 v4와 똑같이 보인다.
