# OWL COMPILE v4 기능 명세 (최우선 기준)

사용자 요청(2026-09-14): ① 라운드 1~7 난이도 설정 ② 블록을 넣으면 옆에서 실시간으로 코드가 네온 연출과 함께 적힘 ③ 블록을 둥글고 매끈하게 ④ 최대 10팀, 팀당 최대 6명 ⑤ 가입하면 대기실에 들어가고, 그 상태에서 진행자가 게임을 만들면 바로 플레이 가능 ⑥ 고급 디자인(`docs/DESIGN_V4.md`).
이 문서가 `docs/WEBSITE_SPEC.md`와 충돌하면 이 문서가 이긴다. 그 밖의 규칙(엔진 의미론, 점수, 페이즈, 패치, 보안)은 그대로다.

## 0. 작업 순서 (의존 관계)

1. **엔진**: R6·R7 추가 (R1~R5와 브리프 수치 불변).
2. **데이터·서버**: 버전형 DB 마이그레이션 → 라운드 선택 → 팀 10·인원 6·역할 공유 → 대기실·자동 배정 → API·SSE → 테스트·e2e.
3. **코드 생성·UI 기반**: 파이썬식 코드 생성(순수 함수), 네온 코드 뷰 컴포넌트, 둥근 블록, V4 디자인 토큰. (1·2와 병렬 가능: 서버 계약에 의존하지 않는다)
4. **화면**: 대기실·홈·인증·관리 / 팀 편집기 / 진행자 / 프로젝터.
5. **검증**: 통합 → 리뷰 → 브라우저 QA.

## 1. 라운드 1~7과 난이도 설정

- 엔진에 R6, R7을 더한다. `GameMap.round`는 1~7, `difficulty`에 `'매우 어려움'` 추가. 표시 난이도는 라운드 번호 = 난이도 레벨(1~7).
  - R6 (어려움, 상한 8, 600초): 새 요소 "함수 속 조건"(벽 따라가기를 함수로 묶어 여러 번 호출). 구덩이 포함 가능, 고양이 없음.
  - R7 (매우 어려움, 상한 10, 720초): 새 요소 "모든 요소"(고양이 순찰 + 열쇠·문 + 구덩이). 잠자기 타이밍과 조건·함수가 모두 필요.
  - 각 라운드는 `rounds/r6.ts`, `r7.ts`에 map·solutions·expect(+naive)를 두고 verify-rounds에 구조·정답·새 요소 필요성(상한 안에서 새 요소 없이 같은 점수 이상 불가) 검사를 추가한다. R1~R5 파일과 수치는 건드리지 않는다.
- 게임을 만들 때 **플레이할 라운드를 고른다**: `rounds: number[]` (1~7 중 1개 이상, 오름차순, 중복 없음). 진행은 고른 라운드만 순서대로.
  - 프리셋: 입문 [1,2,3] · 표준 [1,2,3,4,5] (기본) · 전체 [1..7] · 도전 [4,5,6,7]. 칩 1~7을 눌러 직접 조합도 가능.
- 데이터: `games.rounds` (JSON 텍스트), `games.round` = 현재 라운드 번호(1~7, rounds 안의 값).
- 페이즈: `scored → coding`은 다음 선택 라운드가 있을 때, `scored → finished`는 현재가 마지막 선택 라운드일 때. 되돌리기는 이전 선택 라운드로. 순위표의 라운드 열 = 선택한 라운드들.
- 화면 표기: "R4 · 3/5 · 난이도 4" 형태(라운드 번호, 진행 순번/전체, 레벨).

## 2. 팀 최대 10, 팀당 최대 6명

- `LIMITS.minTeams = 2`, `maxTeams = 10`, `maxMembersPerTeam = 6`.
- 팀 프리셋 10개: 수리부엉이, 올빼미, 소쩍새, 흰올빼미, 금눈쇠올빼미, 칡부엉이, 긴점박이올빼미, 큰소쩍새, 쇠부엉이, 솔부엉이. 색은 V4 팔레트에서 서로 잘 구분되는 10색(디자인 기반 작업에서 확정, 서버는 contracts의 TEAM_PRESETS를 쓴다).
- **역할 공유**: 한 역할을 여러 명이 맡을 수 있다(예: 러너 2명). 한 사람이 여러 역할도 가능. 팀의 서로 다른 사람 수 ≤ 6. 한 사람은 한 게임에서 한 팀만.
  - DB: `members`의 `unique(team_id, role)` 제거 → `unique(team_id, user_id, role)`.
  - 오류: 팀이 가득 참 → 409 `team_full`. `role_taken`은 더 이상 쓰지 않는다.
  - 제출: 그 팀에서 아키텍트 역할을 가진 누구나. 아키텍트가 없는 팀은 타이머 만료 때 자동 봉인된다(기존 규칙). 편집기·진행자 화면에 "아키텍트 없음" 경고.
  - 팔레트: 내가 가진 역할들의 블록. 저장 시 역할 검사(늘어난 블록 id는 내 역할 것) 그대로.

## 3. 대기실 (가입 → 대기 → 게임 생성 → 바로 플레이)

흐름(순서가 핵심):
1. 초대 링크로 **가입하면 바로 `/lobby`(대기실)** 로 간다. 로그인할 때도: 끝나지 않은 게임의 팀원이면 그 게임 `/play/<코드>`로, 아니면 참가자 계정은 `/lobby`, 진행자·관리자는 `/`(홈).
2. 대기실 페이지를 열어 둔 사람 = **대기 중**. (대기실 SSE에 연결된, 끝나지 않은 게임의 팀원이 아닌 로그인 사용자)
3. 진행자는 `/host`에서 **대기실 인원을 실시간으로 보면서** 새 게임을 만든다: 팀 수(2~10, 추천값 = ceil(대기 인원/4), 최대 10), 라운드 선택(§1), 배정 방식:
   - **자동 배정(기본)**: 대기 중인 사람을 들어온 순서대로 팀에 돌아가며 넣는다(사람 i → 팀 i mod T, 팀당 6명까지, 넘치면 대기실에 남고 진행자에게 "자리가 부족합니다" 표시). 팀 안 역할: 순서 [architect, runner, turner, controller]로 k번째 사람에게 k mod 4. 4명 미만 팀은 남는 역할을 앞사람부터 더 맡겨 **4역할이 모두 채워지게** 한다(1명 → 4역할, 2명 → [architect, turner] / [runner, controller], 3명 → [architect, controller] / [runner] / [turner]).
   - **직접 선택**: 대기 중인 사람들은 그 게임의 팀·역할 선택 화면(`/join?code=`)으로 바로 이동한다.
4. 게임이 만들어지는 순간 서버가 대기 중인 각 사람에게 대기실 SSE로 알린다: 자동이면 `{type:'assigned', code, teamId, roles}` → 폰이 `/play/<코드>`로 자동 이동. 직접이면 `{type:'game-open', code}` → `/join?code=<코드>`로 이동.
5. 늦게 온 사람: 이 사람이 **들어갈 수 있는** 열린 자동 배정 게임(로비·코딩 페이즈, 6명 미만인 팀이 있고, 이 사람이 나가거나 내보내지지 않은 게임)이 **정확히 하나** 있으면 대기실에 들어오는 즉시 사람이 가장 적은 팀(6명 미만)에 배정되어 이동한다. 여러 개면 대기실에 "참가할 수 있는 게임" 목록과 참가 버튼. 게임 코드 직접 입력은 보조 수단으로 남긴다.
6. 진행자 도구: 대기실에서 더 데려오기(`POST /api/games/<코드>/pull`, 자동 배정 규칙), 팀원 옮기기(`POST /api/games/<코드>/assign {userId, teamId, roles}`), 내보내기(기존). 내보낸 사람은 대기실로 돌아간다(폰은 게임 채널 `removed`를 받으면 `/lobby`로 이동). 내보낸 사람은 그 게임에 스스로 다시 참가할 수 없다(참가·대기실 참가 버튼 모두 409 `kicked`). 진행자가 데려오기(이름 지정)나 옮기기로만 되돌린다. 게임이 시작된 뒤(코딩 이후) 데려오기는 그 사람이 처음 들어간 팀으로만 넣는다(자리가 없으면 대기실에 남는다).

API·실시간:
- `GET /api/lobby` → `{ me, waiting: [{userId, displayName, username, since}], openGames: [{code, hostName, phase, round, rounds, teams, members, mode, joinable}], myGame: {code} | null }`.
- `GET /api/lobby/events` (SSE): `hello`, `lobby`(대기 인원 변화), `assigned`(본인에게만), `game-open`(대기 중인 사람에게). 대기실 채널은 게임 채널과 같은 버스를 쓰되 채널 id를 따로 둔다.
- `POST /api/games` 본문 `{ teams: 2~10, rounds: number[], mode: 'auto' | 'self' }` → `{ code, assigned: number, leftWaiting: number }`.
- 권한: 대기실 조회·구독은 로그인 사용자. pull·assign은 그 게임 진행자·관리자. 대기 명단에는 표시 이름과 아이디만(다른 개인정보 없음).

## 4. 실시간 코드 뷰 (블록 → 코드, 네온 연출)

- `lib/codegen/python.ts` (순수 함수, 엔진은 건드리지 않음): `toPython(program)` → 줄 목록 `{ text, indent, path | null, blockId | null, tokens: {text, kind}[] }` 와 `pathKey → 줄 번호` 맵.
  - 매핑: 앞으로 `owl.forward()` · 점프 `owl.jump()` · 좌회전 `owl.turn_left()` · 우회전 `owl.turn_right()` · 잠자기 `owl.sleep()` · F 호출 `F()` · 반복 N `for _ in range(N):` · 만약 앞이 벽이면 `if owl.wall_ahead():` · 만약 앞이 구덩이면 `if owl.pit_ahead():` · 아니면 `else:` · 함수 F `def F():`. 들여쓰기 4칸. 빈 몸통은 `pass`. 빈 else는 생략(then이 비면 `pass`).
  - 토큰 종류: keyword, builtin, call, number, punct, comment.
- 편집기(`/play`): 블록 편집기 **바로 옆에** 코드 패널. 블록을 놓거나 옮기거나 지우면 코드가 즉시 바뀐다.
  - 새로 생긴 줄: 타이핑처럼 한 글자씩 나타나고(최대 400ms) 네온 글로우(보라·시안 text-shadow)가 1.2초에 걸쳐 잦아든다. 줄 배경에 빛줄기가 한 번 훑고 지나간다. 바뀐 줄은 짧은 글로우만. 지워진 줄은 빠르게 흐려지며 사라진다.
  - 블록을 놓는 순간 그 블록 카드도 같은 색 네온 테두리가 한 번 번쩍인다(같은 path).
  - 블록에 마우스를 올리면 해당 코드 줄이, 코드 줄에 올리면 해당 블록이 은은하게 강조된다.
  - 코드 패널 머리: "파이썬 | 한국어" 전환(한국어 = 엔진 `toText`), 줄 수, 복사 버튼 없음(베끼기 방지 의미 없음, 단순화).
  - 폰(390px): 블록 아래에 접이식 코드 패널 + 마지막으로 바뀐 줄을 보여 주는 한 줄 네온 티커.
  - `prefers-reduced-motion`이면 타이핑·빛줄기 없이 색만 잠깐 바뀐다.
  - 이 뷰는 **실행 미리보기가 아니다**(시뮬레이터 금지 원칙 유지): 코드만 보여 주고 부엉이를 움직이지 않는다.
- 프로젝터(`/board`)·진행자 콘솔: 같은 코드 뷰(파이썬). 재생 중에는 `Step.path`로 현재 실행 줄을 찾아 네온으로 강조한다(줄 번호가 아니라 path 기준).

## 5. 둥근 블록

모양 규칙은 `docs/DESIGN_V4.md` §4. 연결 구조(위 홈·아래 돌기·C-블록 머리/입/꼬리)는 유지하되 모서리를 크게 둥글리고, 홈·돌기를 부드러운 곡선으로, 면에 은은한 광택 그라데이션을 준다. dnd-kit 규칙·스냅·연결 가능 판정은 그대로.

## 6. 데이터 마이그레이션

- `PRAGMA user_version`으로 버전을 관리한다. 현재 DB는 0(또는 컬럼 추가식 마이그레이션만 적용된 상태)로 보고 v2로 올린다.
- v2: `games`를 새 스키마로 재생성(round 1~7 check, rounds 컬럼 기본 `'[1,2,3,4,5]'`), `members`를 새 제약으로 재생성. 트랜잭션 안에서 `create table new → insert select → drop old → rename`. 외래키 잠시 끔. 기존 데이터(게임·팀원·결과)는 그대로 남아야 한다.
- 테스트: 옛 스키마로 만든 DB 파일을 v2로 올린 뒤 데이터가 같은지 확인하는 vitest.

## 7. 수용 기준 (추가)

1. 게임 생성에서 라운드 칩 1~7과 프리셋이 보이고, 고른 라운드만 진행된 뒤 finished가 된다.
2. 팀 10개 게임을 만들 수 있고, 한 팀에 6명까지 들어가며 7번째는 거절된다. 같은 역할 2명이 각자 블록을 놓을 수 있다.
3. 대기실에 있던 사람들이 진행자가 자동 배정 게임을 만드는 순간 1초 안에 각자 팀 편집기로 이동하고, 모든 팀의 4역할이 채워져 있다.
4. 블록을 놓으면 옆 코드 패널에 해당 파이썬 줄이 네온 연출과 함께 나타나고, 보드 재생 때 실행 줄이 path 기준으로 정확히 강조된다.
5. 기존 수용 기준(R3 150점, R5 18틱 사망 → 패치 → 135점 등)과 e2e는 계속 통과한다.
